# Tour length and the hours that size an ambulance roster

Companion code for an article by Diogo Ribeiro on how the length of a tour (shift) decides which hours set the size of
a roster. It tests a conjecture left by the companion `staffing-shift-constraints`: with tours of one length L, the
hours that bind a roster lie L hours apart, anchored on the steepest change in the daily requirement.

The test rosters FDNY ambulance workload (NYC Open Data, *EMS Incident Dispatch Data*, citywide and in each borough)
and NYC 311 calls over the 52 weeks of 2019, with tours of 6, 8, 9, 10 and 12 hours starting at any hour, each roster
the cheapest an integer programme can find with perfect knowledge of the workload. It compares three rules for where
the binding hours fall: a **comb rule** derived from the dual of the rostering programme, the steepest-climb rule of
the conjecture, and the peak hour.

`PLAN.md` is the pre-registration, written before any EMS record was downloaded.

## Files

- `PLAN.md`: the pre-registration.
- `fetch.py`: records the dataset's columns, downloads the incidents assigned in the test year and writes hourly busy
  time per borough (`sources/ems_hourly.csv`); no incident record is stored.
- `sources/nyc311_hourly_calls.csv`: the hourly 311 counts committed with `staffing-shift-constraints`.
- `staff/data.py`: the grid of test weeks, the loaders and the requirement per hour (Erlang C).
- `staff/comb.py`: combs, the comb bound, comb hours and the comb-rule phase.
- `staff/schedule.py`: rosters of L-hour tours as integer programmes, their relaxation and the binding hours.
- `evaluate.py`: the registered test (`results/summary.txt`, `results/verdicts.json`, tables) and the sensitivity of
  the EMS requirement (`results/sensitivity.txt`).
- `tests/`: unit tests on synthetic data.

## Run

```bash
python -m pip install -r requirements.txt
python -m pytest -q
python fetch.py --sources sources      # downloads only if sources/ems_hourly.csv is not committed
python evaluate.py --sources sources --out results
```

The workflow `.github/workflows/ambulance-tour-length.yml` runs the same steps on pushes to the branch and commits
the sources, results and figures.

## Data

- City of New York, NYC Open Data: *EMS Incident Dispatch Data* (`76xm-jjuj`), generated by FDNY's EMS computer-aided
  dispatch system.
- City of New York, NYC Open Data: *311 Call Center Inquiry* (`wewp-mm3p`), hourly counts as committed with
  `staffing-shift-constraints`.
